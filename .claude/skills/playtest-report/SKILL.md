GaeGGUL Defence의 playtest-report 스킬을 옮긴 것이다(디렉터 승인 단계는 뺐다).
리포트는 `Docs/qa/playtests/playtest-YYYY-MM-DD-[테스터].md`에 둔다.

## 1. 모드
- `new` → 빈 양식을 출력한다.
- `analyze [경로|메모]` → 메모를 읽고 양식을 채운다. 인자가 없으면 메모를 붙여 달라고 한다.

## 2. 양식

```markdown
# 플레이테스트: YYYY-MM-DD [테스터]

## 세션 정보
- 빌드/커밋:
- 기기: 에디터 / Android(기종) / iOS(기종)
- 플레이 시간: 
- 진행 범위: N일차 ~ M일차, 시작 세이브(새 게임 / 이어하기)
- 테스트 목적: (예: 수건 미니게임 난이도, 3일차 월세 압박)

## 첫인상 (처음 5분)
- 목표를 이해했나? 예/아니오/부분
- 조작(드래그, 말풍선 탭)을 이해했나?
- 감정: 몰입 / 헷갈림 / 지루함 / 답답함 / 즐거움

## 핵심 루프
손님 입장 → 시설 이용 → 말풍선·미니게임 대응 → 하루 정산 → 상점 → 다음 날
- 잘 된 점:
- 답답한 점 (심각도 상/중/하):
- 헷갈린 점:
- 좋았던 순간:

## 경제·밸런스
- 일차별 골드 흐름: (일차 / 수익 / 지출 / 월세 / 잔액)
- 파산 위기·여유 시점:
- 미니게임 난이도 체감: (때밀이 / 쓰레기 / 음료 / 수건)
- 손님 수·회전 체감:

## 버그
| # | 내용 | 심각도 | 재현 |
|---|------|--------|------|

## 우선순위 3개
1.
2.
3.
```

## 3. 분석 모드 추가 작업
1. 메모의 관찰을 위 칸에 나눠 넣는다. 테스터가 말하지 않은 수치·감정을 지어내지 않는다. 빈 칸은 "기록 없음".
2. 관련 시스템 카드(`Docs/harness/systems/*.md`)와 실제 데이터(SO 값)를 대조해서, 체감과 설정이 어긋나는 부분을 표시한다.
   예: "수건 미니게임이 너무 짧다" → `Assets/Data/MiniGameData.asset`의 기본 시간·일일 증가량과 `MiniGameBase.StartMiniGame` 공식으로 해당 일차 제한 시간을 계산해서 적는다.
3. 발견을 네 갈래로 분류한다:
   - **설계 변경**: 재미·이해 문제, 규칙이 의도와 다름 → `/quick-design`로 변경안 작성
   - **밸런스**: 수치 체감 문제 → 어느 SO의 어느 값인지까지 적는다
   - **버그**: 재현되는 오동작 → `/bug-report`
   - **폴리시**: 막히진 않지만 거슬리는 것
4. 분류 결과를 보여 준다.

## 4. 저장
"`Docs/qa/playtests/playtest-YYYY-MM-DD-[테스터].md`에 저장할까요?"라고 묻고, 승인하면 폴더를 만들고 저장한다.
버그로 분류된 항목이 있으면 각각 `/bug-report`로 등록할지 묻는다.

GaeGGUL Defence의 brainstorm 스킬을 옮긴 것이다. 원본은 "게임 콘셉트를 0부터" 만드는 절차였지만,
이 프로젝트는 이미 핵심 루프가 있으므로 **기존 게임에 붙일 아이디어**를 만드는 쪽으로 바꿨다.
결과는 `Docs/design/ideas/[주제]-YYYY-MM-DD.md`.

## 0. 현재 게임 파악 (짧게)
- 핵심 루프: 손님 입장 → 동선 따라 시설 이용 → 말풍선·미니게임 대응(만족도) → 하루 정산(수익−지출−월세) → 상점 해금 → 다음 날. 골드가 음수로 다음 날을 맞으면 파산.
- 현재 시설: `Assets/Scripts/Data/FacilityType.cs`, 미니게임: 때밀이·쓰레기·음료·수건, 상점 아이템: `Assets/Data/Shop/`.
- 필요하면 `Docs/harness/README.md` 색인에서 관련 카드를 읽는다. 이미 있는 것을 새 아이디어처럼 내지 않는다.

## 1. 방향 잡기 (AskUserQuestion으로 2~4개만)
- 주제: 시설 / 미니게임 / 손님 / 이벤트 / 경제·성장 / 연출 (인자로 왔으면 생략)
- 지금 게임에서 아쉬운 점: 단조로움 / 돈이 너무 쉬움·어려움 / 손이 할 게 없음 / 바빠서 정신없음 / 목표가 없음
- 원하는 느낌: 바쁘게 돌아가는 맛 / 꾸미는 맛 / 단골이 생기는 정 / 성장하는 맛
- 제약: 작업 기간(하루 / 일주일 / 그 이상), 새 그림이 필요한지

답을 3~4문장 **작업 방향 요약**으로 정리해 확인받는다.

## 2. 아이디어 내기 (3~5개)
세 가지 방법을 섞는다:
- **동사부터**: 플레이어가 손으로 하는 행동(문지르기, 끌어 놓기, 타이밍 탭, 고르기)에서 출발
- **섞기**: 목욕탕 + 다른 일상 소재(찜질방 계란, 우유 자판기, 때타월 판매, 단골 할머니)
- **느낌에서 거꾸로**: 원하는 감정 → 그걸 만드는 규칙

안마다:
```markdown
### [이름]
- 한 줄: 
- 플레이어 행동: (터치·드래그 등 구체적으로)
- 루프 연결: 어디서 돈·만족도·시간에 영향을 주나
- 기존 코드 재사용: (예: FacilityBase 상속, MiniGameBase 상속, ShopItemDataSO 추가, RouteStep에 단계 추가)
- 새로 필요한 것: (그림, 새 시스템, 저장 필드)
- 규모: S(하루) / M(일주일) / L(그 이상)
```
목록으로 보여 주고 마음에 드는 것을 고르게 한다(복수 선택 가능).

## 3. 고른 안 다듬기
- **하루 안에서의 흐름**: 언제 등장하고, 플레이어가 몇 번 손을 대고, 하루 정산에 어떻게 찍히는가
- **며칠에 걸친 흐름**: 해금 시점(상점 가격·일차), 난이도 증가(MiniGameDataSO 방식 재사용 여부)
- **경제 영향**: 수익·지출을 대략 숫자로. 현재 `FacilityIncomeData`, `RentData` 값과 비교해 너무 크거나 작지 않은지
- **하지 않을 것**: 이 아이디어가 커지지 않게 경계선 2~3개

## 4. 범위 판단
- 최소판(하루~이틀): 핵심 행동만, 임시 그림
- 목표판: 연출·밸런스 포함
- 위험: 기술적으로 막힐 수 있는 곳(길찾기, 정렬, 저장 호환)

## 5. 저장과 다음 단계
"`Docs/design/ideas/[주제]-YYYY-MM-DD.md`에 저장할까요?"라고 묻고 저장한다.
다음 단계 제안:
- 되는지부터 보고 싶으면 → `/prototype`
- 바로 붙일 만큼 작으면 → `/quick-design`

## 원칙
- 결정은 사용자가 한다. 안을 고르거나 버리는 건 묻고 진행한다.
- 다른 상용 게임을 그대로 베끼는 안(이름·캐릭터·그림·고유 시스템 복제)은 내지 않는다. 장르 관습은 써도 된다.
